## 1. Запуск работы агентов (сейчас)

Игра ещё не собрана — «запуск» = старт пайплайна по ТЗ.

### Шаг A — оркестратор
В чате Cursor:

```
Роль: orchestrator
SSOT: docs/FULL-SPEC.md
Скилл: docs/skills/orchestrator.md
Секции: §0 §1 §14
Сделать: выдать первую задачу Phase 1 (battle + min content)
```

### Шаг B — первая реализация (Phase 1)
Оркестратор (или ты вручную) поднимает **два** узких агента:

**1) content**
```
Роль: content
SSOT: docs/FULL-SPEC.md
Скилл: docs/skills/content.md
Секции: §2 §10 §7.2 §7.3
Сделать: минимальный набор JSON — 3 стартера + ≥12 карт (по 4 на стартера)
Не делать: баланс сезонов, ферма, клан-босс
DoD: файлы в content/cards валидны, все 5 ролей не обязательны — но 3 стартера tank/fighter/support есть
```

**2) battle**
```
Роль: battle
SSOT: docs/FULL-SPEC.md
Скилл: docs/skills/battle.md
Секции: §2 §3 §7.2 §8.2 §13
Сделать: репозиторий/пакет mythfel-battle — симулятор 3v3 vs bot по seed
Не делать: Unity UI, магазин
DoD: один golden replay: стартовая тройка побеждает тестовый stage
```

### Шаг C — дальше по AGENTS.md
`client` → `backend` → `liveops` → hub/shop → `qa` по §13 → soft launch.

**Не запускать** clan/farm агентов до soft launch.

### Шаг D — Phase 4 Soft launch (§14)
Авто §13 зелёный → in-repo обвязка ограниченного гео + CDN stub + device smoke checklist.

```bash
./qa/run-soft-launch.sh          # §13 + geo example + CDN :ephemeral smoke
cd liveops && go run ./cmd/cdn-stub -geo soft-launch/geo_allowlist.example.json
# → http://localhost:8090/v1/liveops.json  (ЗАПУСК §3)
```

Чеклисты: `qa/SOFT_LAUNCH.md`, `qa/DEVICE_SMOKE.md`.  
**Не** коммитить production CDN keys / store credentials — только stub signature + example geo.

## 3. Запуск приложения (локальный manual QA)

Код Phase 1–4 в монорепо. **Unity Editor-проекта пока нет** — runnable path = LocalSmoke + stubs (без store secrets).

| Сервис | Команда |
|---|---|
