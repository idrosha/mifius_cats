# Правила документирования (Mythfel / Мифиус)

Цель: один источник правды на тему, без копипасты и «теневых» правил в коде.

## Куда писать

| Тема | Файл | Кто |
|---|---|---|
| Механика боя, скоуп SL, экономика ядра | `docs/FULL-SPEC.md` (§) | `design` |
| Player-facing числа/лор/вики | `docs/game-wiki.md` | `wiki` / `design` |
| Locked product decision (почему так) | `docs/DECISION-LOG.md` | любой + апрув Andrew при Locked |
| LiveOps числа/флаги/офферы | `liveops/CHANGELOG.md` + JSON | `liveops` |
| Роли агентов / анти-waste | `docs/AGENTS.md` | orchestrator |
| Как запускать | `ЗАПУСК.md` | — |
| UI IA / nav | `docs/nav-ia.md`, stitch docs | `web-hud` / `stitch` |

Конфликт: **FULL-SPEC > wiki > код-комменты**. Код не SSOT.

## Когда писать

1. Меняешь правило игры → патч **того же §** FULL-SPEC в том же PR/задаче.
2. Меняешь только HUD/презентацию без механики → **не** трогай FULL-SPEC; при спорном UX → запись в DECISION-LOG (Proposed).
3. Баланс/конфиг → строка в `liveops/CHANGELOG.md` (+ id решения, если есть).
4. Новая «док ради доки» без дыры в таблице выше → **не писать** (AGENTS правило №3).

## Как писать

- Коротко: дифф решения, не пересказ всего SSOT.
- Ссылки на § / id решения (`D-0xx`), не дублировать таблицы чисел.
- Player-facing RU; код/ключи — как в репо (`shop_*`, `starter_*`).
- Скриншоты/логи >50 строк → путь к файлу, не вставка в док.
- Дата в журнале/changelog: `YYYY-MM-DD`.

## Чего не делать

- Не плодить второй FULL-SPEC / «v2 rules» / Axie-вики.
- Не фиксировать store API (Steamworks/IAP) в SSOT без отдельной задачи.
- Не оставлять исключения только в коде («временно так»).
- Не писать крипту/NFT/Axie-имена в player docs.
